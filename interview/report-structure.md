# 最终作品结构（呈现规范 · 生成 HTML 的骨架）

> **用途**：定义最终作品 `interview-review.html` 从上到下的板块结构。下次整理评测结果按本文组织。
> **配套**：`eval-capability-matrix.md` 是**数据层**（评什么、6 类数据、能力主表）；本文是**呈现层**（作品长什么样、先讲什么后讲什么）。
> **总原则**：先产品结论、后技术证据；术语 `English`（中文）；区分项干净数据出来前标 `*待重跑确认`。

## 作品骨架（10 个板块，从上到下）

| # | 板块 | 写什么 | 数据来源 |
|---|---|---|---|
| ① | **Hero：产品结论 + 决策建议** | 一句话：两个模型质量同档，DeepSeek 便宜一半、更快；规模化选 DeepSeek、关键任务用 Opus。副标注置信度 | `comparison.productConclusion` + 选型判断 |
| ② | **为什么这么评** | 不能只看视频做没做出来，要看过程能不能托付（可控 / 失败恢复 / 安全 / 人工接管成本）→ 所以评 trace（执行轨迹） | 固定文案 |
| ③ | **怎么评（受控方法）** | 拿一个现成视频 workflow 当"统一考场"，同 baseline / prompt / 隔离执行（控变量） | 固定文案 |
| ④ | **★ 我做的评测工具（作业核心）** | 见下方详述——这是作业主交付物，给足存在感 | 工具文件 + 固定文案 |
| ⑤ | **能力覆盖主表** | `eval-capability-matrix.md` 第二节的 7 列主表 | metrics（结果列）|
| ⑥ | **性价比对比（突出板块）** | 成本 / 速度 / 质量同档——结论核心，单独拎出来做重点 | 数据全集第 3 类 |
| ⑦ | **失败恢复故事** | 重跑后：某模型出了什么错、怎么自救的具体案例（比一个数字有冲击力） | trace errors + recovery |
| ⑧ | **Outcome 验收 + 安全（门槛，简短）** | 一句话：都达标（含硬字幕烧录）、都守住安全线 | 数据全集第 2、4 类 |
| ⑨ | **★ 选型决策建议（灵魂）** | 什么场景用谁、为什么：规模化 / 流程清晰 → DeepSeek（省一半）；关键 / 高可靠 / 研究严谨 → Opus | 综合判断 |
| ⑩ | **置信度与边界** | 单轮观察、待第二轮稳定性；不评视频审美 / TTS 音质 / Memory | `confidence` |

> 必须有、但 2 个表里没有的是：① Hero 结论、④ 工具板块、⑨ 选型建议。缺这三块，作品就只是"一堆数据"，不是"评测产品经理的作品"。

## ④ 工具板块详述（作业核心，重点写"为什么这么做"）

这是你作业的主交付物，作品里要单独、突出地讲清楚：

**1. 解决什么问题**
> raw trace（原始执行轨迹）又长又技术，产品面试官没法直接读。我的工具把它压缩成"产品能看懂的证据、档位和结论"。

**2. 工具原理（三个工具，全是纯规则代码、零 LLM 调用）**

| 工具 | 角色 | 怎么工作（原理）| 用 LLM 吗 |
|---|---|---|---|
| `compare-traces.mjs` | grader（评测器）| 读 `trace.stream.jsonl` + 各 manifest → 用**计数和正则**抽信号（读了哪些文件、跑了哪些命令、几个错误、成本/耗时、来源数、canary 是否泄露）→ 用**写死的规则**打分、映射成档位 → 输出 `metrics.json` + `report.md` | ❌ 纯规则 |
| `render-interview-html.mjs` | 展示器 | 读 `metrics.json` → 套 HTML 模板渲染 → 面试页。无判断、纯渲染 | ❌ 纯规则 |
| `check-sandbox-baseline.mjs` | 公平性校验 | 跑前校验 worktree 不含评测文件，防被测模型偷看评分标准（防泄题）| ❌ 纯规则 |

**3. 为什么坚持纯规则、不用 LLM 当裁判（这是"客观"的根，必讲）**
> 同一份 trace 跑十遍，结果完全一样；每个分数都能反查到是**哪条规则、哪个字段**算出来的。这避免了"用一个 AI 主观评判另一个 AI"的不可复现问题。**客观 = 标准人定、数据机器从轨迹自动抽，不是我拍脑袋打分。**

**4. 诚实的边界（被追问时答）**
> 规则只能评**可量化**的（读没读文件、几个错误、几个来源）；**软质量**（研究深不深、报告好不好）用可量化的代理信号近似。要评更深的软质量，下一步可加一个 LLM 辅助评分层，但会和确定性指标**分开标注**，不让主观污染客观。

**5. 可复用性（升华到"评测能力"）**
> 这套工具 + 评测方法换个任务、换个模型都能复用。我交付的不是"Opus vs DeepSeek 谁赢"的一次性答案，而是**一套能持续评 Agent 能力的方法和工具**——这才是评测产品岗要的东西。

## 呈现纪律

- **不手改 `interview-review.html`**：所有内容由 `render-interview-html.mjs` 按本结构渲染。
- **门槛 vs 区分**：门槛板块（⑧）一句话带过证明"都能干活"；把版面和讲解重量给区分板块（⑥性价比、⑦失败恢复、⑨选型）。
- **信息分层**：产品层（①⑥⑨ 结论与决策）显眼；证据层（⑤ 主表 + 各卡片）其次；原始指标 / 完整信源放审计层（折叠或附录），别糊产品面试官一脸数据。
