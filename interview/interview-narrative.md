# 面试讲解方案

## 一句话

这是一个面向豆包 Agent 生产力评测产品岗的小型评测工具：我让 Opus 和 DeepSeek 在 Claude Code 里做同一个 30 秒视频生成任务，用 trace 判断谁更适合复杂生产力 Agent 场景。

## 为什么选这个任务

产品上要回答的是：哪个模型更稳定地把一句需求推进成可交付结果，过程中风险在哪里，人工接管成本有多高，哪些能力可以沉淀成评测标准。

单纯调用一次视频接口太薄，测不出这些差异，也测不出 Claude Code 的核心能力。

这个任务要求模型在已有 `workflow-sandbox` 里完整走一遍视频生成流程：

```text
理解需求 -> 写分镜 -> 生成多张图片 -> 生成对应音频 -> 拼接成片 -> 处理失败 -> 跑 hook -> 做 subagent 审查 -> 安全检查 -> 交付报告
```

这条流程足够暴露模型差异，但对面试官来说很好理解：就是从一句需求到一条可交付视频。

## 现场展示顺序

1. 先说明为什么评：Agent 生产力评测要看过程可控、失败恢复、安全边界和人工接管成本。
2. 再说明任务设置：同一个视频主题、同一个项目、同一个起始 commit、同一套检查命令。
3. 展示两个模型的 outcome：视频结果、图片和音频产物、manifest、报告、检查结果。
4. 展示 trace 对比：读规则、用 skill、跑脚本、hook、subagent、失败恢复、安全边界、复验、最终总结。
5. 给产品结论：哪个模型更适合复杂生产力 Agent 任务，风险是什么，项目约束还要怎么补。

## 重点讲法

```text
我把视频生成当作受控生产流程，不把它当审美题。

我看的是 trace：它有没有读项目规则，有没有复用已有 workflow，有没有用脚本和检查命令，有没有处理失败，有没有触发 hook 和 subagent 审查，有没有守住密钥和路径边界，最后能不能把结果讲成业务方能理解的交付报告。
```

## 避免的讲法

- 不讲“六层可视化页面”。
- 不讲复杂 dashboard。
- 不把 Claude Code 能力讲成工具清单。
- 不用视频审美判断模型优劣。
- 不说这是一个完整视频生产系统。
