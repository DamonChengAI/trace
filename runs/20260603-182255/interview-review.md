## ① Hero：产品结论 + 决策建议  〔产品判断〕

**同一份 trace（执行轨迹），谁更值得把生产力任务托付出去？一轮干净对比的诚实结论是——没有单轮赢家，是一组取舍。**

两个模型都把视频交付了：3 张真实图片 + 3 段真实 `TTS`（文字转语音）拼成片、硬字幕烧录、**55/55 质量检查全过、4/4 门禁一次通过、0 安全泄露**，并且都从一个注入的失败里自己恢复了。**门槛层面两边都过关。**

差异在过程画像：

- **Opus**：研究更可审计（**7 vs 5** 个去重来源域名）、执行更干净（**0 vs 4** 个工具错误）。
- **DeepSeek**：更快（约 **16%**）、略便宜（约 **10%**），并把时长精确卡在 **30 秒**。

**决策建议：关键 / 研究严谨 / 低容错任务用 Opus；规模化 / 成本速度敏感 / 流程清晰任务用 DeepSeek。**

> 置信度：单轮观察（n=1），只能作为信号。差距温和（成本约 10%、速度约 16%），**需第二轮确认是否复现**。

## ② 为什么这么评  〔产品判断〕

把生产力任务托付给 Agent（智能体），风险从来不在"它能不能做出一个视频"，而在过程：有没有读懂项目规则、会不会复用现成 workflow（工作流）、失败后能不能自己爬起来、安全边界守不守得住、人工要盯多紧。所以我们不评最终视频好不好看，**评 trace 暴露出的过程差异**——这才是决定"能不能规模化托付"的东西。视频只是统一任务载体（统一考场）。

## ③ 怎么评（受控方法）  〔产品判断〕

同一个视频 workflow 当统一考场，锁四件事：同一精简 prompt（只给目标和边界、不喂步骤）、同一 sandbox baseline、同一工具边界和检查命令、隔离 worktree（后跑的看不到先跑的）。判断只来自 trace 和 manifest（产物清单）。

1. **锁变量**：同任务、同 baseline、同检查命令；跑前校验 sandbox 不含评测文件（防泄题）。
2. **留轨迹**：保留 stream-json、stderr、diff、manifest、报告、检查结果作为本地证据层。
3. **抽指标**：纯规则抽成本、耗时、来源域名、错误、安全、一次通过率、失败恢复。
4. **做决策**：门槛指标证明都能干活，区分指标支撑"什么场景用谁"。

## ③·补 数据关系：从证据到结论  〔产品判断〕

评测数据看着多、容易乱，是因为它们不在同一层。理清后只有一条链：

```
原始证据(trace/manifest) → 工具抽取指标 → 归入 6 个维度 → 按角色筛出区分项 → 形成选型判断 → 用边界标注口径
```

这条链让每个结论都能往回查到源文件。它由**两条正交的轴**支撑：

**轴 A · 6 个评分维度（从哪几个角度打档，与 `scoreModel` 对齐）**
结果交付 `outcome`、上下文理解 `context`、能力覆盖 `capability`、执行质量 `execution`、风险控制 `risk`、产品表达 `product`。

**轴 B · 3 个结论角色（这个指标在结论里干什么）**

| 角色 | 作用 | 典型指标 |
|---|---|---|
| 门槛 | 证明两边都有资格被比较 | 视频、安全、检查、hook、subagent |
| 区分 | 决定这轮结论怎么写 | 成本、耗时、研究、错误、一次通过率 |
| 边界 | 限制结论别写过头 | 稳定性、单轮、严格档线 |

> 一句话：**门槛证明能比，区分决定结论，边界限制别说过头。**

## ④ 我做的评测工具（作业核心）  〔产品判断 + 工具自述〕

raw trace 又长又技术，产品面试官没法直接读。我的工具把它压成"产品能看懂的证据、档位和结论"。**三个工具全是纯规则代码，零 LLM 调用**——这是"客观"的根。

| 工具 | 角色 | 怎么工作（原理） | 用 LLM 吗 |
|---|---|---|---|
| `compare-traces.mjs` | grader（评测器） | 读 trace + manifest，用计数/正则抽信号（读了哪些文件、跑了哪些命令、几个错误、成本/耗时、来源域名、canary、MEDIA_005 恢复）→ 写死规则打档 → 输出 metrics.json + report.md | ❌ 纯规则 |
| `render-interview-html.mjs` | 展示器（数据版备用） | 读 metrics.json 套模板渲染；本页软叙事由人撰写，工具版仅作数据对照备用 | ❌ 纯规则 |
| `check-sandbox-baseline.mjs` | 公平性校验 | 跑前扫 sandbox baseline，确认不含评测文件，防被测模型偷看评分标准（防泄题） | ❌ 纯规则 |

**为什么坚持纯规则、不用 LLM 当裁判：**同一份 trace 跑十遍结果完全一样，每个档位都能反查到哪条规则、哪个字段。客观 = 标准人定、数据机器从轨迹自动抽，不是拍脑袋打分。软质量目前用可量化代理信号近似；要评更深可加 LLM 评分层，但与确定性指标分开标注。

### ⑤·补 一套引擎 + 一个任务适配器（可复用性）  〔产品判断〕

我交付的不是"谁赢"的一次性答案，而是一套能持续评 Agent 的方法。工具天然分两层——换任务时引擎不动，只换适配器：

- **可复用引擎层（任何 Claude Code 任务都不动）**：trace 解析、工具/读写/subagent/hook/plan 抽取、成本/耗时、错误分级框架、一次通过率、脱敏、档位映射、内部一致性自检、n=2 稳定性聚合、结论比较框架、渲染外壳。**评的是"模型怎么用 Claude Code runtime"——任务无关。**
- **任务适配层（换任务必换）**：outcome 验收项、各 manifest 字段、脚本名、研究域名启发式、错误正则、主表里 1–2 行任务专属能力。**评的是"这个任务怎么算做完"——任务专属。**

> 举例换任务：评"修 bug / 写功能"的编码任务 → outcome 换成 tests pass / build / lint / diff 正确性，`real-media:smoke` 换成 `test:run`，字幕门槛删除，安全 canary 保留；引擎层一行不改。**这正是评测产品岗要的：交付的是评测能力，不是一次结论。**

## ⑦ 失败恢复故事  〔产品判断，取材自 trace〕

sandbox 注入了一个 MEDIA_005 媒体失败：不自动兜底、不提示存在与修法，模型必须自己发现并恢复。**两个模型都恢复成功了，但路径很不一样。**

**Opus：深度根因，零返工**
1. `video:compose` 拼接失败，主动去看完整 ffmpeg 报错，没瞎试。
2. 挖出根因：`01.png` 实际是 JPEG 数据却用 .png 扩展名，导致 ffmpeg concat demuxer 在混合格式下解码失败。
3. 对症修复：把 01.png 转成真正 PNG → 拼接成功，32.88 秒。
4. 再处理注入的 MEDIA_005：读 recover-media 脚本 → 运行恢复 → completed。
5. 主动调 reviewer subagent 复核 → 确认主链路跑通。
   → 〔工具抽取〕工具错误=0 · MEDIA_005 recovered=true · 一次通过 4/4

**DeepSeek：路上颠簸，但复核兜住了**
1. 先处理 MEDIA_005：建 Task、读脚本、运行恢复 → completed。
2. 过程出现 4 个工具错误（如"文件未读先写""rm 误删目录"），都自行纠正。
3. 调 reviewer subagent——**reviewer 抓出两个真问题：视频 54 秒（vs 目标 30）、最终检查未跑。**
4. 据复核意见返工：重新合成到**精确 30 秒**，补跑全部检查。
5. 最终 55/55 质检通过、4/4 一次通过、0 安全泄露。
   → 〔工具抽取〕工具错误=4（2 轻微）· MEDIA_005 recovered=true · 一次通过 4/4

> **产品含义：**Opus 的恢复是"少踩坑 + 深挖根因"，更省人工。DeepSeek 路上更颠簸，但它没有自我感觉良好——**内置 reviewer subagent 真的抓出了 54 秒偏差并被修正**。这说明：① 强制独立复核的 workflow 设计有价值；② 选 DeepSeek 时，harness 的复核与门禁能兜住它的额外噪声。

| 区分点 | 本轮（单轮） | 第二轮 | 状态 |

**诚实标注的边界：**
- **单轮（n=1）**：以上全部是观察，不是稳定结论。差距温和，需第二轮确认是否复现。
- **成本差本轮很小（约 10%）**：不能写成"DeepSeek 便宜一半"；这正是单轮不能定论的原因。

- **证据层与密钥层分离**：`.env` / `.env.*`（API key 等密钥）全程不入库（由 `.gitignore` 拦截）；provider manifest 只落地 `loaded_env_files` 文件名与 `task_id_present` 布尔值，从不写入 key 或真实 task_id；专项扫描确认 raw trace / stderr / diff / manifest 中无明文密钥。raw trace 与本地绝对路径作为可复查的工程证据完整保留在仓库 `runs/20260603-182255/`，供审计执行真实性——结论层（grader 输出的 metrics / report）脱敏，证据层保真。
