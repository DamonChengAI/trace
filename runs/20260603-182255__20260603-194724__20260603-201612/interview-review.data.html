Agent 生产力评测：从 trace 里看谁更值得托付。

这份作品把 Claude Code 的 trace（执行轨迹）翻译成产品判断：成本、效率、研究可复查、失败恢复、安全边界和人工接管成本。

三轮门槛两边都过、都能托付；区分项稳定拉开差距但各有胜负——Opus 稳定在 真实来源数、报错数 更强，DeepSeek 稳定在 单次成本、端到端耗时 更强。结论写成“交付门槛同档、按场景选型”，不是单一默认基线（n=3，只判复现、不做统计显著性）。

主角是一套可复用、可反查、产品能看懂的 Agent（智能体）评测方法。模型胜负只作为这套方法的第一组验证案例。

置信度
n=3，用途是验证关键差异是否复现；不算方差，不给两位小数总分。

本页结构
10 个板块：结论、原因、方法、工具、能力主表、性价比、失败恢复、门槛验收、选型、边界。

数字口径
研究质量按去重来源域名数，不按 URL 正则计数；成本按 total_cost_usd / run。

②

为什么这么评

不能只看视频有没有生成。生产力 Agent 真正的风险在过程：它有没有读懂项目规则、能不能复用现成 workflow（工作流）、失败后是否自救、安全边界有没有守住，人工接管成本高不高。

视频只是统一任务载体。评的是 Agent（智能体）能否把一句目标稳定推进成可验收结果，并把过程沉淀成可复查证据。

③

怎么评

拿同一个视频 workflow 当统一考场，锁住 prompt（任务提示）、baseline（基线版本）、工具边界、检查命令和隔离 worktree（工作目录）。所有判断来自 trace 和 manifest（产物清单）。

1. 锁变量

同一任务、同一 baseline、同一检查命令，两个模型互相看不到对方产物。

2. 留轨迹

保留 stream-json、stderr、diff、manifest、报告和检查结果。

3. 抽指标

纯规则抽成本、耗时、来源域名、错误、安全、一次通过率。

4. 做决策

门槛项证明能不能干活，区分项支撑什么场景用谁。

④

raw trace 又长又技术，产品读者没法直接读。工具把它压成产品能看懂的证据、档位和结论。判定层（门槛和区分）全用规则代码、不靠 LLM、可复现；规则碰不到的软质量另设一层由 Opus 4.8 评、标注分开。
