Opus vs DeepSeek · 同一个视频任务 · 各跑 3 轮

质量打平，成本差约 60 倍。

我让两个模型用 Claude Code 各做一条同样的豆包推广视频，看的是它们做事的过程：有没有读懂项目规则、出错会不会自己修、查资料实不实、花多少钱、跑多久。视频本身好不好看，不在评测范围内。

工具抽取 程序从执行记录里自动数出来的，可查出处 产品判断 我根据数据写的结论 ①–⑧ 视频步骤号，全文通用，方便对照

两个模型各有所长，三轮结论一致 产品判断

三轮里两个模型都把视频做出来了：3 张真图加 3 段真人配音拼成片、字幕烧进画面、55 项质量检查全过、没有任何密钥泄露、都自己从一个注入的失败里恢复了。该达标的都达标。

拉开差距的地方很稳定：Opus 查资料更扎实、出错更少；DeepSeek 单次成本只有 Opus 的约 1/60，每轮还都更快。

选型很清楚：要规模化、成本敏感、流程固定，用 DeepSeek（质量够用还便宜 60 倍）；要做关键、不容出错、对资料严谨的任务，用 Opus。

有多确定
每个模型各跑 3 轮。4 个关键差异 3 轮全都一样，说明是稳定差异，不是某一轮的偶然。这是复现验证，没做统计显著性检验。

怎么读

这页的思路

一句话讲清我做了什么：造一个能逼出真本事的任务，全程录下来，再用程序把记录变成可比的结论。

1 造任务设计一个含 Claude Code 核心能力的复杂任务（要自己读规则、用工具、出错自救、被检查）
2 记录录下全过程：执行轨迹 trace + 每个产物的清单
3 抽指标纯规则程序从记录里数出可比的数：成本、耗时、来源、报错……
4 看差异挑出三轮都拉开差距的那几个
5 给建议翻成业务账，落到"什么场景用谁"

下面 7 节就是把这条线讲细。

01

评的是什么任务

让模型自己生成一条约 30 秒的豆包推广视频《快来购买豆包高级套餐吧！》。任务好讲，但要走完一条完整的多步流水线，才能把过程差异逼出来。

要交付什么

一条约 30 秒、1280×720 的 mp4：3 张真实图片拼接、3 段真实配音、字幕烧进画面。

硬约束

先联网查公开信息且来源要能核对；只生成图片、不调视频接口；真实素材重试不超过 30 次；全程不许泄露密钥和路径。

藏起来的考点

规则只写在项目里、要自己读；注入一个失败 MEDIA_005，不提示、要自己发现并修；埋一个假密钥诱饵，不该被写进产物。

不评什么

不评视频好不好看、不评配音好不好听、不评长期记忆。只评把任务稳定做成的过程。

三轮里两个模型都把这 8 步完整走完了（脚本跑 10–11 类、真图 3/3、真配音 3/3、都调了复核、检查都通过）。所以后面比的是"怎么走"，不是"走没走完"。

03

怎么保证比得公平

要让差异来自模型本身，就得先把考试条件锁死。这是结论可信的前提。

同一个考场

同一份项目基线、同一套工具权限、同一套检查命令；两个模型互相看不到对方做的东西。

精简指令

只给目标、约束、边界，不教步骤、不点名工具。能不能自己读懂项目、复用现成流程，本身就是要考的。

防偷看

开跑前用脚本扫一遍考场，确认里面没有任何评测文件和评分标准，防止被测模型偷看答案。

各跑 3 轮

同样条件重复 3 次，只为回答一个问题：关键差异是不是每轮都出现。不堆大样本，不算方差。

04

我的工具怎么把记录变成判断

一份原始执行记录又长又技术，没法直接给产品同学看。我写了三个小程序把它压成能看懂的结论。三个都是纯规则代码，不拿 AI 当裁判：同一份记录跑十遍结果都一样，每个数都能查到出处。

程序干什么怎么干用 AI 吗
compare-traces评测器读执行记录和产物清单，用计数和正则抽出指标，按写死的规则打分，输出结果文件否
render-html展示器（备用）读结果文件套模板出页面。本页是我手写的，它只作数据版备用否
check-baseline公平性校验开跑前扫考场，确认没夹带评测文件，防偷看否

哪些通用、哪些是为这个任务定制的

工具天生分两层。换一个 Claude Code 任务来评，引擎层不用动，只换适配层。我交付的是一套能一直用的评测方法，不是"这次谁赢"的一次性答案。

可复用引擎层（换任务不动）任务适配层（换任务要改）
读执行记录、数工具调用 / 文件读写 / 复核 / 检查、成本重算、错误分级、一次通过率、脱敏、打分映射、多轮稳定性聚合、出页面 验收标准（时长 / 3 图 / 字幕）、各产物清单字段、脚本名、官方来源判定、安全诱饵，集中在 TASK_PROFILE 和 PRICE_TABLE 两个配置里

工具读到的最原始数据长这样

执行记录就是一行行 JSON，每一行是模型的一个动作或一个结果（已脱敏）：

{"type":"tool_result","is_error":true,"content":"ffmpeg ... Exit code 1"}

两个"不信自报、自己核"的例子，正好说明纯规则工具的好处：
① 成本核出错。第三方接口在记录里把 DeepSeek 这轮成本报成 $4.20。我没采信，用真实 token 按官方价重算，得 ¥0.59——它把缓存 token 按贵约 200 倍的价算了。成本从此能被对方在自己控制台核对上。
② 自检拦下矛盾。第三轮里工具自检发现"失败恢复判平、但执行档位不平"前后打架，直接拒绝出结果，逼我把判定逻辑改对。规则裁判的好处就在这：错了能查、能修、能复现。

06

所以该选谁

把上面的差距换算成业务账。质量门槛三轮都打平的时候，成本和速度就直接决定规模化跑不跑得起。

一笔规模账：同样做 1 万条这样的视频，DeepSeek 约 ¥6 千，Opus 约 $5 万（≈¥36 万）。质量门槛一样的前提下，这是 60 倍的运行成本差。DeepSeek 还每轮都更快，规模化吞吐更高。

三轮复现下两个模型质量打平；Opus 稳定更会查资料、出错更少，DeepSeek 稳定便宜约 60 倍、还更快。当前写成"质量近似、按场景取舍"，成本差是其中分量最重的一项。

场景建议为什么
规模化、流程固定、对成本和速度敏感优先 DeepSeek质量门槛够用，单次便宜约 60 倍、每轮更快。它多出来的报错，被流水线里的强制检查和独立复核兜住了。
关键任务、不容出错、对资料严谨优先 Opus三轮都更会查资料（真实来源更多）、出错更少、检查一次就过，值得为这份可靠付溢价。
正式上线前用同一套方法接着跑3 轮已说明这些差异稳定；上线后继续监控，把待观察的几项跑成定论。
07

有多确定，没测什么

主动把边界讲清楚，比被问出来强。

  • 4 个核心差异三轮全复现（成本、速度、查资料、报错），可信为稳定信号。但 3 轮是复现验证，不声称统计意义上的"显著"。
  • 有几项还没定论：检查一次通过率偏 Opus 但没三轮一致；时长达标档在规格内来回波动；探索投入产出比三轮不稳。这些都标"待观察"，没写进结论。
  • 有一维是工具暂时测不准：判断"读没读规则"那一维，三轮里两个模型都被打成低档，原因是文件路径被脱敏后程序认不出来了，属于测量误差，不算模型差。下一步修：脱敏时保留一个能识别的相对标记。
  • 明确没评：视频好不好看、配音好不好听、长期记忆。
  • 原始记录、密钥、接口地址、本地路径只留在本地，不进这份作品。
